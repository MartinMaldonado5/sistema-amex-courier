2. PRUEBA 1 - MOTOR ORIGINAL (PowerShell + Excel COM)
----------------------------------------------------
- Ejecucion 1 via pagina web: 124,03 s -> 151 guias, 149 coincidencias,

- Ejecucion 2 via pagina web: 140,79 s -> mismos conteos.

3. PRUEBA 2 - ALTERNATIVA PYTHON + OPENPYXL (prototipo temporal)

4. PRUEBA 3 - PROTOTIPO C# + OPEN XML SDK (lectura/escritura por filas)
-----------------------------------------------------------------------
- Se descargo el SDK .NET 10.0.401 (portable, solo para compilar) y el
  paquete oficial DocumentFormat.OpenXml 3.3.0 desde NuGet.
- El prototipo lee cada hoja TIB como flujo XML fila por fila (sin cargar
  la hoja completa en memoria), arma un indice por WR y parchea una copia
  del inventario fila por fila.
- Resultado con archivos reales: 17-21 s -> 151 guias, 149 coincidencias,
  2 sin coincidencia, 433.127 filas, 0 duplicados. Memoria maxima ~330 MiB.
- Archivo ZIP integro, misma hoja y dimensiones, ninguna celda fuera de las
  5 columnas objetivo fue alterada, validacion Open XML sin errores nuevos.
- Conclusion: ~6 VECES MAS RAPIDO que Excel COM. Candidato elegido para
  integrar. (Compilacion: 0 errores, 0 advertencias.)

5. REGLA DE TIPO PARA TRACKING (decision tomada: SIEMPRE TEXTO)
--------------------------------------------------------------
- El Tracking identifica un envio, no es una cantidad. Excel COM convierte
  automaticamente textos con apariencia numerica a numero: en una prueba,
  el tracking "000123" termino como 123 (se pierden los ceros iniciales)
  y valores con guion pueden interpretarse como fecha.
- El motor C# ahora guarda TODO Tracking como texto: conserva "000123" y
  los caracteres exactos. Si el TIB ya trae 123 como numero, se escribe
  como texto "123" (los ceros perdidos en el origen no se pueden recuperar).
- Peso se guarda como numero cuando el valor de origen lo permite.

6. INTEGRACION DEL MOTOR C# A LA APLICACION
-------------------------------------------
- processor/AmexInventoryProcessor/ : proyecto C# de produccion (6 argumentos:
  inventario, 3 TIB, Excel de salida, CSV de sin-coincidencia; responde un
  solo JSON por stdout). Incluye validacion de contenedor .xlsx (max 20.000
  componentes y 1 GiB descomprimido), copia atomica del inventario y
  escritura de CSV con proteccion anti-inyeccion de formulas.
- Se publico como ejecutable autocontenido win-x64
  (AmexInventoryProcessor.exe, ~80 MB): el usuario final NO instala .NET.
- server.js: invoca al .exe, nuevo endpoint /api/unmatched/<id> (CSV),
  respuesta con unmatchedCount + unmatchedSample (500) + duplicateWRs (200),
  limpieza automatica de ejecuciones de mas de 30 dias (RUN_RETENTION_DAYS),
  /api/health ahora reporta "processor":"openxml".
- public/: la pagina muestra muestra + conteo total y enlace de descarga
  del CSV completo; nota de que Tracking se guarda como texto.
- Iniciar automatizador.bat, LEEME.txt e INSTRUCCIONES_PARA_WHATSAPP.txt:
  ya NO piden Excel ni .NET, solo Node.js 18+; el .bat verifica el .exe.
- process_excel.ps1 quedo como legado sin uso (se puede borrar).

9. PARA USAR EN OTRA COMPUTADORA (ver LEEME.txt)
------------------------------------------------
- Requisitos minimos: Windows 10/11 de 64 bits + Node.js 18 o superior.
  NO necesita Microsoft Excel, NO necesita .NET, NO necesita internet
  (todo el proceso es local en http://127.0.0.1:8765).
- Pasos: 1) Extraer todo el ZIP en una carpeta. 2) Doble clic en
  "Iniciar automatizador.bat". 3) Cargar inventario + 3 TIB (.xlsx).
  4) "Completar inventario" y descargar el Excel (y el CSV si hay guias
  sin coincidencia). 5) Cerrar la ventana negra al terminar.
- Verificacion rapida: abrir http://127.0.0.1:8765/api/health debe mostrar
  "status":"ok" y "processor":"openxml".
- Limites: 100 MB por carga, 20 min por proceso, 1 GiB descomprimido por
  libro, encabezados en las primeras 25 filas, 1 trabajo a la vez.
- Los resultados quedan en runs/ y se borran solos a los 30 dias.
